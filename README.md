# E.form — Ερωτηματολόγιο με dashboard αποτελεσμάτων (δωρεάν)

Ένα μοντέρνο ερωτηματολόγιο με ζωντανό dashboard, που τρέχει **εντελώς δωρεάν**:

| Κομμάτι | Πού τρέχει | Κόστος |
|---|---|---|
| Φόρμα + dashboard (HTML/CSS/JS) | GitHub Pages | 0 € |
| Backend (αποθήκευση/ανάγνωση) | Google Apps Script | 0 € |
| Βάση δεδομένων | Google Sheet | 0 € |

Χωρίς Node server, χωρίς npm, χωρίς build step. Μόνο απλά αρχεία.

**Τι περιλαμβάνει**

- **Φόρμα:** λιτή, «χάρτινη» σχεδίαση με τυπογραφία Commissioner (πλήρη ελληνικά). Ο τίτλος εμφανίζεται λέξη-λέξη με χειρόγραφη υπογράμμιση, και δίπλα του υπάρχει 3D αξονομετρία με τις ερωτήσεις σαν φύλλα σχεδίου, που ανοίγουν καθώς κάνετε scroll. Η ερώτηση στο κέντρο της οθόνης ξεχωρίζει διακριτικά. Υπάρχουν ακόμα λεπτή μπάρα προόδου, κλίμακα βαθμολογίας σαν χάρακας, αυτόματη αποθήκευση προχείρου, ανοιχτό και σκούρο θέμα. Δουλεύει άψογα και στο κινητό.
- **Dashboard:** σύνδεση με κωδικό, βασικοί δείκτες (KPIs), γράφημα απαντήσεων στον χρόνο, γράφημα για κάθε ερώτηση επιλογής ή βαθμολογίας, μέσος όρος, πίνακας με τα ελεύθερα κείμενα και αναζήτηση, φίλτρα χρόνου, ανανέωση, «Live» αυτόματη ανανέωση και εξαγωγή σε CSV.
- **Ασφάλεια:** δείτε την ενότητα [🔐 Ασφάλεια](#-ασφάλεια).

> **Content-Security-Policy**, που μπλοκάρει οποιοδήποτε «ξένο» script.

## 🚀 Εγκατάσταση βήμα-βήμα

### Βήμα 1 — Google Sheet + Apps Script + κωδικός διαχειριστή

1. Ανοίξτε το [sheets.google.com](https://sheets.google.com) και δημιουργήστε ένα **νέο κενό υπολογιστικό φύλλο**.
   Δώστε του ένα όνομα, π.χ. «Απαντήσεις ερωτηματολογίου».
2. Από το μενού πατήστε **Επεκτάσεις → Apps Script** (Extensions → Apps Script).
   Ανοίγει νέα καρτέλα με έναν editor κώδικα.
3. Σβήστε ό,τι υπάρχει στο αρχείο `Κώδικας.gs` / `Code.gs`, **επικολλήστε ολόκληρο** το περιεχόμενο του
   [`apps-script/Code.gs`](apps-script/Code.gs) και πατήστε 💾 **Αποθήκευση** (Ctrl+S).
4. **Ορίστε τον ADMIN_KEY** (τον κωδικό του dashboard). Ο κωδικός **δεν γράφεται μέσα στον κώδικα**:
   αποθηκεύεται στις *Ιδιότητες σεναρίου* (Script Properties), που λειτουργούν όπως ένα αρχείο `.env`.
   Διαλέξτε **έναν** από τους δύο τρόπους:

   **α) Εύκολος τρόπος (προτείνεται):**
   1. Στη γραμμή εργαλείων πάνω από τον κώδικα, από τη λίστα συναρτήσεων διαλέξτε **`setup`**.
   2. Πατήστε ▶ **Εκτέλεση** (Run).
   3. Την πρώτη φορά θα σας ζητηθούν άδειες (δείτε το [Βήμα 2.4](#άδειες)).
   4. Στο **Αρχείο καταγραφής εκτέλεσης** (Execution log) θα εμφανιστεί ένας τυχαίος κωδικός 32 χαρακτήρων.
      **Αντιγράψτε τον και φυλάξτε τον** κάπου ασφαλές, π.χ. σε password manager.

   **β) Χειροκίνητος τρόπος:**
   1. Πατήστε ⚙️ **Ρυθμίσεις έργου** (Project Settings) στο αριστερό μενού.
   2. Κατεβείτε στις **Ιδιότητες σεναρίου** (Script Properties) → **Προσθήκη ιδιότητας σεναρίου**.
   3. Ιδιότητα: `ADMIN_KEY` · Τιμή: ένας δικός σας κωδικός, **τουλάχιστον 16 χαρακτήρες** (καλύτερα 24+, τυχαίοι).
   4. **Αποθήκευση ιδιοτήτων σεναρίου**. Μετά τρέξτε μία φορά το `setup` (όπως στο α), για τις άδειες και για τη δημιουργία της καρτέλας.

> ⚠️ Μην αλλάξετε τη γραμμή `const ADMIN_KEY_PROPERTY = 'ADMIN_KEY';` στον κώδικα. Εκεί γράφεται
> μόνο το **όνομα** της ιδιότητας, όχι ο κωδικός.

### Βήμα 2 — Ανάπτυξη ως Εφαρμογή Ιστού

1. Πάνω δεξιά πατήστε **Ανάπτυξη → Νέα ανάπτυξη** (Deploy → New deployment).
2. Δίπλα στο «Επιλογή τύπου» πατήστε το ⚙️ και διαλέξτε **Εφαρμογή ιστού** (Web app).
3. Συμπληρώστε:
   - **Περιγραφή:** π.χ. `v1`
   - **Εκτέλεση ως:** **Εγώ** (Me)
   - **Ποιος έχει πρόσβαση:** **Οποιοσδήποτε** (Anyone). *Όχι* «Οποιοσδήποτε με λογαριασμό Google».
4. <a id="άδειες"></a>Πατήστε **Ανάπτυξη** και **αποδεχτείτε τις άδειες**:
   - **Εξουσιοδότηση πρόσβασης** → διαλέξτε τον λογαριασμό σας.
   - Αν δείτε «*Η Google δεν έχει επαληθεύσει αυτήν την εφαρμογή*», αυτό είναι φυσιολογικό, γιατί η εφαρμογή είναι δική σας.
     Πατήστε **Σύνθετες ρυθμίσεις** → **Μετάβαση στο … (μη ασφαλές)** → **Να επιτρέπεται**.
5. **Αντιγράψτε το URL της εφαρμογής ιστού**. Μοιάζει έτσι και **πρέπει να τελειώνει σε `/exec`**:
   ```
   https://script.google.com/macros/s/AKfycb.................................../exec
   ```

**Γρήγορος έλεγχος:** ανοίξτε το URL σε μια νέα καρτέλα. Πρέπει να δείτε:
```json
{"ok":false,"error":"unauthorized"}
```
Αυτό σημαίνει ότι όλα δουλεύουν: το backend απαντά και **αρνείται** να δώσει δεδομένα χωρίς κωδικό. 👍

### Βήμα 3 — Επικόλληση του URL στο `config.js`

Ανοίξτε το [`docs/config.js`](docs/config.js) και αντικαταστήστε τη γραμμή:

```js
scriptUrl: 'https://script.google.com/macros/s/ΕΠΙΚΟΛΛΗΣΤΕ_ΕΔΩ_ΤΟ_ID_ΤΗΣ_ΑΝΑΠΤΥΞΗΣ/exec',
```

με το δικό σας URL από το Βήμα 2.5. **Μόνο το URL. Ποτέ τον κωδικό.** Το `config.js` το βλέπουν όλοι.

### Βήμα 4 — Ανέβασμα στο GitHub και ενεργοποίηση του Pages

1. Ανεβάστε τα αρχεία στο repository σας στο GitHub, στο branch `main`
   (με `git push` ή από τη σελίδα του repo: **Add file → Upload files**).
2. Στο repo πατήστε **Settings → Pages**.
3. Στο **Build and deployment**:
   - **Source:** `Deploy from a branch`
   - **Branch:** `main` και φάκελος **`/docs`** → **Save**
4. Περιμένετε 1–2 λεπτά και ανανεώστε τη σελίδα. Θα εμφανιστεί *«Your site is live at …»*.
5. Τσεκάρετε το **Enforce HTTPS**, αν δεν είναι ήδη τσεκαρισμένο.

> Στο δωρεάν πλάνο του GitHub, το Pages δουλεύει μόνο με **δημόσιο** repository. Γι' αυτό ο κώδικας
> έχει σχεδιαστεί έτσι ώστε **να μην υπάρχει κανένα μυστικό μέσα στο repo**.

### Βήμα 6 — ⚠️ ΣΗΜΑΝΤΙΚΟ: όταν αλλάζετε το `Code.gs`

Το URL `/exec` τρέχει **την έκδοση που αναπτύξατε**, όχι ό,τι βλέπετε στον editor. Κάθε φορά που
αλλάζετε τον κώδικα στο Apps Script:

1. 💾 Αποθήκευση.
2. **Ανάπτυξη → Διαχείριση αναπτύξεων** (Deploy → Manage deployments).
3. Διαλέξτε την ανάπτυξή σας → ✏️ **Επεξεργασία** (Edit).
4. **Έκδοση:** διαλέξτε **Νέα έκδοση** (New version) → **Ανάπτυξη**.

Έτσι **το URL μένει το ίδιο** και δεν χρειάζεται να αλλάξετε το `config.js`.
❌ *Μην* κάνετε «Νέα ανάπτυξη» κάθε φορά, γιατί δημιουργεί **νέο URL**.

> Οι αλλαγές στις **Ιδιότητες σεναρίου** (π.χ. νέος ADMIN_KEY) ισχύουν αμέσως, χωρίς νέα έκδοση.

## 🎨 Εταιρική ταυτότητα (χρώματα, λογότυπο, γραμματοσειρά)

Όλη η εμφάνιση προσαρμόζεται από **τρία σημεία**:

1. **Χρώματα:** στην κορυφή του [`docs/style.css`](docs/style.css), στο μπλοκ «Μάρκα».
   Αλλάζετε το `--brand` (το κύριο χρώμα) και, αν θέλετε, το `--ink` (το χρώμα των κουμπιών).
   Υπάρχει ξεχωριστό μπλοκ για το σκούρο θέμα, όπου καλό είναι να μπει μια λίγο ανοιχτότερη απόχρωση.
2. **Λογότυπο:** βάλτε το αρχείο μέσα στο `docs/`, π.χ. `docs/assets/logo.svg`, και στο `config.js` γράψτε
   `logo: 'assets/logo.svg'`. Δεκτά είναι μόνο τοπικά αρχεία (`.svg`, `.png`, `.webp`, `.jpg`), ώστε να ισχύει το αυστηρό CSP.
3. **Όνομα:** στο `config.js`, `brand: '…'`. Εμφανίζεται στη μπάρα, στον τίτλο της καρτέλας και στο υποσέλιδο.

> Η γραμματοσειρά **Commissioner** (άδεια SIL OFL, στο `docs/fonts/`) φορτώνεται από τον ίδιο τον
> ιστότοπο, χωρίς Google Fonts: δεν μοιράζεται η IP των επισκεπτών με τρίτους. Για άλλη γραμματοσειρά, βάλτε
> τα αρχεία `.woff2` στο `docs/fonts/` και αλλάξτε τα `@font-face` και το `--font` στην κορυφή του `style.css`.

## ✏️ Αλλαγή ερωτήσεων

Όλες οι ερωτήσεις είναι στο [`docs/config.js`](docs/config.js), στο `questions: [...]`. Τύποι:

```js
{ id: 'source',  type: 'choice',   label: 'Ερώτηση;', options: ['Α', 'Β', 'Γ'], required: true }
{ id: 'topics',  type: 'multi',    label: 'Ερώτηση;', options: ['Α', 'Β', 'Γ'], maxSelections: 2 }
{ id: 'score',   type: 'rating',   label: 'Ερώτηση;', min: 1, max: 5, labels: ['Κακό', '', '', '', 'Τέλειο'] }
{ id: 'nps',     type: 'rating',   label: 'Θα μας προτείνατε;', min: 0, max: 10 }  // 0–10 → δείχνει και NPS
{ id: 'name',    type: 'text',     label: 'Ερώτηση;', maxLength: 200 }
{ id: 'notes',   type: 'textarea', label: 'Ερώτηση;', maxLength: 1000, placeholder: '…' }
```

Κανόνες για το `id`:

- λατινικά γράμματα, αριθμοί ή `_`, να ξεκινά με γράμμα (π.χ. `satisfaction`, `q4_reason`)
- γίνεται **όνομα στήλης** στο Sheet, οπότε **μην το αλλάζετε** αφού αρχίσουν να έρχονται απαντήσεις
- μια νέα ερώτηση δημιουργεί αυτόματα νέα στήλη, και οι παλιές απαντήσεις μένουν ανέγγιχτες

Μετά από κάθε αλλαγή στο `config.js` κάντε commit και push. Το GitHub Pages ενημερώνεται σε 1–2 λεπτά.
Δεν χρειάζεται καμία αλλαγή στο Apps Script.

## 🔐 Ασφάλεια

### Γιατί δεν υπάρχει αρχείο `.env` στη σελίδα;

Το GitHub Pages σερβίρει **στατικά αρχεία**: ό,τι υπάρχει στον φάκελο `docs/` το κατεβάζει ο browser
του κάθε επισκέπτη. Ένα `.env` στη σελίδα θα ήταν **δημόσιο**. Γι' αυτό τα μυστικά ζουν **μόνο στον server**,
δηλαδή στις **Ιδιότητες σεναρίου** του Apps Script, που είναι το «`.env` του Google». Το `.gitignore`
εμποδίζει επίσης να ανέβουν κατά λάθος στο GitHub αρχεία όπως `.env` ή `credentials.json`.

### Τι προστατεύεται και πώς

| Κίνδυνος | Προστασία |
|---|---|
| Να δει κάποιος τις απαντήσεις | Το `doGet` δίνει δεδομένα **μόνο** με σωστό `ADMIN_KEY`. Η σύγκριση γίνεται σε σταθερό χρόνο, ώστε να μη «διαρρέει» ποιοι χαρακτήρες ήταν σωστοί. |
| Διαρροή του κωδικού | Δεν υπάρχει στον κώδικα ούτε στο GitHub. Ζει στις Ιδιότητες σεναρίου. Στο dashboard κρατιέται μόνο στο `sessionStorage` της καρτέλας και σβήνεται όταν την κλείσετε. |
| Μαντεψιά κωδικού (brute force) | Ελάχιστο μήκος 16 (το `setup` φτιάχνει 32 τυχαίους), καθυστέρηση σε κάθε λάθος, κλείδωμα μετά από 20 λάθη σε 10 λεπτά. |
| Πρόσβαση στο Google Sheet / Drive | Το Sheet μένει **ιδιωτικό**, γιατί το script τρέχει «ως Εγώ». Οι επισκέπτες δεν αποκτούν **καμία** πρόσβαση στο Drive σας. Μην κάνετε κοινή χρήση του Sheet. |
| Spam και τεράστια δεδομένα | Όριο μεγέθους αιτήματος (20 KB) και απάντησης (2000 χαρακτήρες), έως 40 πεδία, έλεγχος τύπων, όριο 60 υποβολών/λεπτό, «παγίδα» (honeypot) για bots, απόρριψη συμπλήρωσης σε κάτω από 1,5″, προστασία από διπλές υποβολές. |
| Χαμένες ταυτόχρονες απαντήσεις | `LockService`: οι εγγραφές μπαίνουν μία-μία. |
| **Formula injection** (π.χ. απάντηση `=IMPORTXML(...)` που «κλέβει» δεδομένα όταν ανοίξετε το Sheet) | Κείμενα που ξεκινούν με `= + - @` αποθηκεύονται ως απλό κείμενο, τόσο στο Sheet όσο και στο CSV. |
| **XSS** (κακόβουλος κώδικας σε μια απάντηση) | Το dashboard δεν χρησιμοποιεί ποτέ `innerHTML` με δεδομένα. Όλα μπαίνουν ως απλό κείμενο. Επιπλέον, το **CSP** μπλοκάρει κάθε script που δεν είναι δικό μας. |
| Αλλοιωμένο Chart.js από το CDN | **SRI hash** (`integrity`): αν αλλάξει έστω ένα byte, ο browser δεν το εκτελεί. Η έκδοση είναι κλειδωμένη (4.6.1). |
| Clickjacking (το dashboard μέσα σε ξένο iframe) | Το dashboard κρύβεται αμέσως αν φορτωθεί μέσα σε iframe. |
| Διαρροή μέσω referrer, cookies ή μηχανών αναζήτησης | `no-referrer`, τα αιτήματα στέλνονται **χωρίς cookies**, και το dashboard έχει `noindex`. |
| Ξεχασμένο ανοιχτό dashboard | Αυτόματη αποσύνδεση μετά από 20 λεπτά αδράνειας. Τα δεδομένα κρατιούνται μόνο στη μνήμη της καρτέλας. |
| Λεπτομέρειες σφαλμάτων | Ο server απαντά μόνο με κωδικό σφάλματος (π.χ. `server_error`). Οι λεπτομέρειες πάνε μόνο στα δικά σας logs. |

### Τι δεν μπορεί να κρυφτεί (και γιατί είναι εντάξει)

- **Το URL του Apps Script είναι δημόσιο.** Η φόρμα πρέπει να ξέρει πού να στείλει, άρα όποιος ανοίξει
  τον κώδικα της σελίδας το βλέπει. Μπορεί μόνο να *στείλει* απαντήσεις (με όλα τα παραπάνω όρια),
  **όχι** να τις διαβάσει.
- **Ο κωδικός ταξιδεύει ως `?key=` στο αίτημα του dashboard.** Το αίτημα είναι κρυπτογραφημένο (HTTPS)
  και δεν μένει στο ιστορικό του browser, αλλά το βλέπουν οι servers της Google.
  Χρησιμοποιήστε τυχαίο κωδικό, που δεν τον χρησιμοποιείτε πουθενά αλλού.
- Κανένα δωρεάν σύστημα χωρίς CAPTCHA δεν σταματά 100% έναν αποφασισμένο spammer. Τα όρια όμως κρατούν τη ζημιά μικρή.
- **Προαιρετική επιπλέον προστασία:** στο `Code.gs` γράψτε τα id των ερωτήσεών σας στο
  `ALLOWED_FIELDS` (π.χ. `['source', 'satisfaction', 'improve']`) και βγάλτε νέα έκδοση (Βήμα 6).
  Έτσι ο server θα απορρίπτει κάθε άλλο πεδίο.

### ✅ Checklist ασφαλείας

- [ ] Ο `ADMIN_KEY` είναι τυχαίος και ≥ 24 χαρακτήρες (το `setup` φτιάχνει 32).
- [ ] Ο κωδικός **δεν** υπάρχει σε κανένα αρχείο του repo (ούτε στο `Code.gs`, ούτε στο `config.js`).
- [ ] Το Google Sheet **δεν** είναι κοινόχρηστο («Περιορισμένη» πρόσβαση).
- [ ] Ο λογαριασμός Google και ο λογαριασμός GitHub έχουν **επαλήθευση 2 βημάτων**.
- [ ] Στο GitHub: **Settings → Code security → Secret scanning** ενεργό.
- [ ] Αν ο κωδικός διαρρεύσει: τρέξτε `rotateAdminKey` στον editor. Ο παλιός σταματά να ισχύει αμέσως.

## 🧪 Τοπική δοκιμή (προαιρετικό)

Δεν χρειάζεται τίποτα να εγκαταστήσετε. Αν έχετε Python:

```bash
python3 -m http.server 8000 --directory docs
```

Μετά ανοίξτε το http://localhost:8000 (φόρμα) και το http://localhost:8000/dashboard.html.

## 🎨 Προσβασιμότητα και λεπτομέρειες

- Πλήρης χρήση με πληκτρολόγιο, σωστές ετικέτες για screen readers, ορατό focus.
- Σέβεται τη ρύθμιση του συστήματος **«Λιγότερη κίνηση»**: τα animations απενεργοποιούνται.
- Κάθε γράφημα έχει και **«Προβολή ως πίνακας»**, ώστε οι τιμές να διαβάζονται χωρίς χρώμα ή ποντίκι.
- Το CSV ανοίγει σωστά στο Excel με ελληνικούς χαρακτήρες (UTF-8 με BOM).
